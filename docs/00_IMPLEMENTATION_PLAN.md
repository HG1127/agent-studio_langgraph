# Agent Studio 可执行落地计划 V1.0

日期：2026-10-10  |  状态：基线计划，开发验收以实际测试为准

## 一、项目目标

面向无编程经验用户：一句话描述期望助手 → AI 生成可编辑 AgentSpec → 授权知识与工具 → 沙盒真实试运行 → 检查质量与权限 → 一键发布到 Web → 查看任务、费用与质量。专业用户可进入可视化编排和配置模式，但不应需要从零编写 Prompt 或调用 API。

**唯一北极星指标**：在预置工具可用、模型和账户完成授权的情况下，非技术用户完成“创建且成功执行首次任务的 Agent”的比例及用时；内部目标：≥80% 测试用户在 15 分钟内完成标准模板的首次运行（需通过实际可用性测试验证）。

## 二、不可妥协的落地约束

1. 所有 Agent 共享版本化 AgentSpec；自然语言修改必须生成结构化差异，不直接混入不可审计的 Prompt。
2. 采用单个权威运行状态来源：正式版以 LangGraph 检查点 + 数据库任务/事件为主；队列只负责唤醒执行者，不独立保存第二份业务状态。
3. 所有工具必须注册 JSON Schema、可见范围、授权策略、超时与调用记录；写操作默认要求后端审批。
4. 模型输出不是事实：检索事实需要来源；用户数据和外部网页不得提升为系统权限。
5. 标准暂停、恢复、停止与预算必须由 Runner 实施；浏览器断线不得导致后台任务内容丢失。
6. 首版不做通用市场、复杂多 Agent、A2A 和完整 Computer Use，这些是 P2。
7. 开发/演示与生产状态必须明确分离；不提供假“成功”状态。
8. 主仓库、业务需求、验收测试与版本号保持一致；以实际测试证据决定是否进入下一里程碑。

## 三、六个阶段与交付门槛

| 阶段 | 参考周期 | 工作包 | 明确交付/阶段关口 |

## 五、人员分工（建议）

- 产品负责人 1：需求确认、优先级、非技术用户访谈与验收。
- 交互/视觉设计 1：三种编辑模式、设计系统、可用性。
- 前端工程师 1–2：Next.js、编辑器、任务进度、发布页面。
- 后端/Agent 工程师 2–3：AgentSpec、LangGraph、工具、模型、状态/记忆、API。
- 平台/DevOps 1：数据库、队列、沙盒、CI/CD、可观察性与安全基础设施。
- QA/安全（可兼职）1：自动测试、故障注入、多租户与审批安全。

## 六、功能依赖与优先级

P0-1 基础：用户工作空间 → AgentSpec 版本 → 工具授权 → 任务与事件 → 审批/限额 → Eval → 发布。
P0-2 内容：文档解析、知识索引与 Context 策略，在有权限作用域之后接入。
P1：工作流画布/定时/模板市场/配额计费/灰度，依赖 P0 稳定的数据结构与发布。
P2：多 Agent/A2A/Computer Use/自主优化，必须有沙盒和可回滚发布。

## 七、质量门禁（Go / No-Go）

- G0：README 的环境步骤可重复执行；静态检查、后端单测和 API 契约通过。
- G1：真实模型生成配置、真实模型工具调用、Run/Event 查询、失败路径及终止规则可复现。
- G2：12 项要素逐项有后台测试；读写权限/跨租户隔离测试零严重问题；发布与回滚通过。
- G3：20 名非技术用户执行标准任务，目标 ≥80% 15 分钟内完成；灾备演练、运维与成本审计完成。
- 任何“工具模拟成功”“没有处理重复外部写入”“未授权可访问其他租户数据”都属于阻断发布问题。

## 八、主要风险和应对

| 风险 | 触发信号 | 措施 |
| --- | --- | --- |
| LLM 生成不可执行配置 | Schema 校验/工具匹配失败率高 | AgentSpec AST + 校验 + 交互补齐，禁止执行任意模型生成代码 |
| 工具权限失控 | 发现模型可绕过审批 | 服务端 Tool Gateway 统一检查，风险分级与审计 |
| 任务状态错乱 | 重启/超时/重复消息导致多次操作 | 一致性检查点、幂等键、事件顺序、有限重试 |
| 成本不可控 | 单任务请求数/费用突增 | 分级配额、预算/超时控制、熔断、显示真实使用量 |
| UX 复杂 | 用户在连接器/流程画布流失 | 对话默认、一页关键确认、技术配置折叠 |
| 第三方组件许可与可维护性 | SaaS 许可/升级限制 | 优先 MIT/Apache 组件；引入前法务/升级评估 |
| Python 3.14 兼容性 | Agent 依赖不支持 | 推荐容器内 Python 3.12/3.13，使用锁定依赖 |
| 数据泄露与提示词注入 | 非法跨租户检索/工具越权 | 行级访问、秘密托管、低信任文本隔离、自动化安全测试 |

## 九、当前真实进度

已发现目标 WebCodex 项目目录为空、不是 Git 仓库。S0 的代码骨架、文档和测试属于本轮新增工作；未完成的模块一律维持 TODO。模型密钥、生产域名、云资源、邮箱发送授权、持久化 PostgreSQL 环境均需后续配置或明确选择。

## 十、下一次开发的明确优先级

1. 先让 API / Web 能本地启动并可验证，不依赖未配置的外部服务。
2. 写版本化 AgentSpec Schema、错误定义与第一批结构化工具。
3. 打通一个配置有效且具真实模型凭据的运行闭环，保存 Run/Events。
4. 增加 LangGraph + PostgreSQL checkpoint 并补断线恢复，开始 S1。
5. 落实多租户和授权后，再公开访问与添加外部写操作。
